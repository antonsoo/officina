# Recorded tasks and visible PDF ink

Two concrete evidence failures motivated these changes: a missing benchmark
record became an observed failure, and another glyph's ink became support for
a covered PDF digit. The catalogue now links the public task-cohort case. Its
Fieldproof card keeps the separate CORD receipt study; the authored PDF controls
below address a different question.

## Errorbars: preserve the recorded comparison

The retained public SWE-bench submission contains 441 task records and 359
resolutions. The converter previously filled the other 59 task slots with
zeroes, despite an explicit evaluated-task mask. Comparing this manufactured
500-task record to a complete peer introduced 41 peer-only successes and 18
invented joint failures.

The [native input, actual baseline and independent oracle](https://github.com/antonsoo/errorbars/tree/661ff9988b1bb8f78854b8068423a3b87045099e/studies/observed-cohorts)
retain the evidence. The official 359/500 score stays 71.8%. The observed subset
does not establish full-benchmark performance, random missingness, or a cause for
the absent records. This is a correction to the supported paired comparison.

All 174 complete CSV exports remain byte-identical. The fixed 500-task study and
browser exclude the incomplete packet explicitly: 172 complete, score-consistent
submissions remain, including 77 above the study's score threshold. The older
catalogue's 78-submission / 1-of-874 finding is superseded; the corrected study
has one unadjusted significant comparison among 842 gaps under three points.
The card instead surfaces the more consequential native-cohort reproduction.

The [summary correction](https://github.com/antonsoo/errorbars/tree/661ff9988b1bb8f78854b8068423a3b87045099e/studies/summary-inference)
also makes the CLI's primary summary honor recorded repository groups. On the
retained 500-task Sonar/Opus submission, the point estimate remains 79.2%, while
its interval changes from [75.64%, 82.76%] to [70.03%, 88.37%]. Independent
general-design CR2/SciPy calculations check all 173 retained summaries. A single
group retains its descriptive mean and unavailable uncertainty.

The [publication receipts](https://github.com/antonsoo/errorbars/tree/661ff9988b1bb8f78854b8068423a3b87045099e/studies/observed-cohorts/results)
separate source, installed wheel/source distribution and hosted bytes. The
corrected public calculator was deployed and checked in both browser engines,
including phone layouts and offline downloads. PyPI remains version 0.2.4;
the tested pinned-source install is documented in the project's quickstart.

## Fieldproof: do not borrow another glyph's overhang

The [authored renderer-bounds study](https://github.com/antonsoo/fieldproof/tree/b1ddeee4ef21ef73b94dfef4c234ddd62de3b740/studies/native-glyph-bounds)
starts with native `Authorized total: $900.00`, covers the nine, and draws an
italic seven whose advance ends before the nine's layout rectangle. Its ink
extends beyond that advance. The previous overlap observer still verified 900.
Neither the authored page nor the correction establishes a replacement amount.

All 25 covered controls now require review. In 72 independent PDFium/Poppler
omission comparisons, the 25 covered nines change no RGB pixels and the 11
visible nines do. Nine visible controls verify; two retain conservative review
outcomes. These invoices are synthetic, not real receipt error-rate evidence.

The observer now associates source characters with native renderer font
envelopes and bounds possible ink, including transformed stroke widths and
page/Form miter declarations. Failed or ambiguous native associations remain
unavailable. A positive regional contribution still does not prove readability,
correct Unicode mapping, or outline-level pixel ownership.

This costs some specificity: four old rendering-mode controls and 13 old opacity
controls contain visible stroked claims whose possible miter footprints overlap.
They now require review, with their original authored visibility retained. Their
other filled amounts remain usable. All 11 ordinary example documents preserve
their complete verification reports, text and geometry.

The source requires PDFium 5.0 or later for its character-to-object API. The old
4.30 floor cannot establish this native association. Package version 0.2.7 is
unchanged; source installation and a locally built review UI remain separate
from the existing registry package. The static demo uses precomputed examples
and does not run this native loader.

Fieldproof's front page is also reduced from 866 to 184 lines. The tested source
setup appears before the detailed feature list; usage, design, development and
the evidence index have dedicated guides. The wheel's rendered README and the
source distribution retain those links and guides. Fresh setup, actual CLI
output, 100 browser scenarios against the installed server and static demo,
and the 64-page worker control retain
the usable workflow. The two installed worker observations take 11.35 and
14.05 seconds within unchanged limits; they are not performance guarantees.

The catalogue's fresh Node 24 install passes lint, types, formatting, all 38
unit checks and all 32 production browser scenarios. A separate
[card replay](evidence/cohorts-ink-browser.mjs) inspects both revised cards in
Chromium/Firefox at 1440 and 375 pixels, including dark mode, zero page overflow
and no accessibility violations. After visiting both thumbnails, their search
and immutable source links work offline without requests. All eight
[local captures](assets/cohorts-ink-2026-10-17/local/) were visually inspected.
Public-byte and hosted replay receipts identify the subsequent publication stage.
