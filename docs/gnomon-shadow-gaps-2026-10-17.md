# Gnomon: a date curve cannot cross an unlit interval

On a polar-day wall, the former date generator discarded unusable shadow
projections and connected the remaining points. A full-circle plate then
engraved a false segment between separate illuminated branches, in the
preview, native SVG and construction PDF. In the controlled latitude-70,
90 mm example, that segment's midpoint implied 85.49 degrees solar declination
on a 23.44-degree June curve.

The correction preserves every usable coordinate and retains missing sampled
projections as path breaks. Eight north/south, east/west and physical-size
controls produce 20 native vectors: 12 false segments become zero; eight fan
controls remain byte-identical. An independent inverse-Sun calculation reads
actual serialized SVG and PDF paths, without product projection helpers.
This is controlled ideal geometry, not a field or ephemeris accuracy estimate.
The existing 3.75-degree sampling still approximates visibility boundaries.

[Reproduction, actual faulty downloads and unchanged controls](https://github.com/antonsoo/gnomon/tree/main/studies/shadow-gaps)
retain the editable inputs, source hashes and native files. Clean archived
source `7a07466` passed installation, lint/type checking, 308 unit checks in
each of two number locales, independent native metrology and 70 actual browser
workflows. Corrections begin at `0bb1b01`; source `2a3f4f2` and Pages `f28869e`
publish that clean build.

All 33 built files and the canonical root URL match public HTTP bytes. Four
public Chromium/Firefox desktop/mobile contexts disconnect, open the same
editable file, save identical inputs, and download four SVGs and eight A4/Letter
PDFs. Independent measurement finds no false segments in these 12 files and
verifies all 16 sheets' physical 100 mm calibration bars. All eight screenshots
are byte-identical to the reviewed local captures.
